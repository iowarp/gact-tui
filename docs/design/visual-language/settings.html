Open questions
  • A Tools page across plugins? Develop has per-tool settings only in each plugin’s Tools tab. Is the Settings table worth adding?
  • Outcome columns. Show both outcome columns by default, or only the mode column with the script column on demand?
  • Built-in tools. Should Workspace files and Local commands tools appear in the table too?
  • Browser back. v7 let browser back close Settings. This pass uses only × and EscEsc, as you asked. Keep it that way?
  • What search matches. Labels only, or also the ⓘ hints and each section’s keywords? Develop already keeps keywords per section.
  • Window size. About 88% of the app, or full size with the app still showing at the edges?
  • Ctrl K⌘K inside the window. Should the palette open already on the Settings type?
  • Values in results. Should a setting’s current value show at the end of its result row, as drawn?
  • Access rules. They save as one set today. Keep the Save bar for them, or save each rule as you finish it?
  • Inline confirm. Fine for remove, disconnect and cancel? Trust and uninstall-with-cascade stay dialogs.
  • Status words. Dot and word on every row, or the dot alone with the word on hover when the window is narrow?
