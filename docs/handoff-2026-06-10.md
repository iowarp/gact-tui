# clio-agent → gact server: TUI-facing contract changes

**Handoff date:** 2026-06-10
**Range:** changes since Fri 2026-06-05 on `clio-agent` (`feat/model-agnostic-routing`)
**Audience:** gact-tui — only the server-contract / behavior changes the TUI consumes.

---

## 👉 Which clio-agent branch to run against

**Use `clio-agent` on `feat/model-agnostic-routing`** (pushed, tip `680f04f`).

- **NOT `develop`** — develop is a *strict ancestor*, **34 commits behind**, and has **none**
  of the changes below (no `/v1/providers/lm/wait`, no `/v1/providers/{id}/handshake`, no
  `/v1/mcp/handshake`, no new provider-config fields, no `reasoning_log`, old turn-wall
  behavior). Building the TUI against develop will miss every endpoint/field in this doc.
- **NOT `feat/agent-driven-routing`** — that's an in-flight internal-orchestration refactor
  (same tip as `feat/model-agnostic-routing` today; will diverge). It does **not** change the
  HTTP/event contract, so there's no reason to target it.
- Once `feat/model-agnostic-routing` merges into `develop`, switch back to `develop`.

## 🆕 New endpoints

- **`GET /v1/providers/lm/wait?timeout=<sec>`** — long-poll for LM provider readiness.
  Binding is async after `PUT /v1/providers/lm`; poll this instead of racing the first
  turn against a 503. Returns `{state: idle|configuring|ready|error, status_message, error}`.
  *(commit a55df4f, closes #654)*
- **`GET /v1/providers/{provider_id}/handshake`** — report-only per-provider handshake:
  connectivity, auth, discovered models + per-model config (context window, reasoning /
  tool-calling flags). *(8ec9ba0)*
- **`GET /v1/mcp/handshake`** — per-MCP-server readiness for the TUI. Each declared server
  reports connect status + tool count; a down server does not break the others. *(edfdcfd)*

## 🔁 Changed request — `PUT /v1/providers/lm` body (`LMProviderRequest`)

New optional fields (back-compat defaults):

| field | default | meaning |
|---|---|---|
| `temperature` | **0.0** | default CHANGED to 0.0 (deterministic structured output) — surface/override in UI *(cb7ae74)* |
| `max_tokens` | `0` | 0 = server picks (context-aware from the handshake) *(b311bbc, 82d6f99)* |
| `context_length` | `0` | desired LM Studio load window; 0 = server default (avoids the JIT-8192 trap) |
| `parallel` | `0` | LM Studio backend concurrency ("Max Concurrent Predictions"); treated as 1 *(0f32d74)* |

## 🔁 Changed response — `GET /v1/providers/lm` (`LMProviderInfo`)

New handshake-discovered, queryable fields:

- `chosen_context: int|null` — the active/loaded context window actually in use.
- `context_window: int|null` — the model's hard ceiling.
- `is_reasoning: bool`, `native_tool_calling: bool` — capability flags. *(8f14a85, 3b5d2b8)*

## 🆕 New assistant-message metadata keys

In `GET /v1/sessions/{sid}/messages` → `message.metadata`:

- **`reasoning_log`** — per-LM-call `[{model, question, reasoning, response, reasoning_chars}]`
  capturing reasoning models' chain-of-thought for the turn. Gated by `CLIO_CAPTURE_REASONING`
  (default on). New — candidate for a "thinking" panel. *(5fef694)*
- (already present, FYI: `expert_handoffs`, `tools_called`, `agent_runtime`, `prompt_resolution`,
  `stream_source` / `stream_fallback`.)

## ⚙️ Behavioral / semantic changes (no schema change, but affect UX)

- **Turn watchdog:** the per-turn *wall clock* is gone — turns are bounded by a
  **no-progress watchdog**, not total duration. A long-but-progressing turn (and now an
  actively-*reasoning* turn, which can stream tens of thousands of reasoning tokens with no
  answer text) must NOT be rendered as "stuck"/timed-out. *(769c944, 5fef694)*
- **Shell approval:** bounded **read-only / text-reshape `shell_bash`** is now auto-approved
  server-side (no permission prompt for those); other shell still prompts. *(f724b59, 7d543dd)*
- **MCP spawn/reload semantics:** domain tools come **only from declared MCP servers**
  (in-process domain servers removed); stdio MCPs are **spawned per active workspace** with
  `cwd = workspace root`; tool artifacts are grounded to the workspace root. The TUI's
  tools/health view should read from `/v1/mcp/handshake` + mounted tools, not assume the old
  in-process tool set. *(c8014e2, aace3ae, 59e21f7, 6b30136)*
- **workflow_state** is now a typed dict OutputField that bubbles through nested children
  (typed, not inferred) — relevant if the TUI renders state/evidence. *(fcbd12c, 40318f0, 0b543e3)*
- **Install/env:** the launcher exports `CLIO_KIT_PATH` and `CLIO_ALLOWED_ROOTS`
  (default `$HOME:/tmp`). *(a539e44, 87832b4)*

## ⚠️ Removed / deprecated

- Scattered model-discovery paths are unified behind the handshake; the old in-process domain
  servers + `clio_kit_bridge` are gone. If the TUI referenced any of those, repoint to the
  handshake / MCP endpoints. *(82f322f, c8014e2, a845177)*

### Heads-up: in-flight (NOT yet landed)

A larger refactor is on `clio-agent` branch `feat/agent-driven-routing`: moving multi-expert
routing out of the server's deterministic continuation-contract state machine into
agent-emitted `expert_handoffs`. When it lands it will change how/when the parent re-enters
and how "done" is signaled — but the **HTTP/event contract above is not expected to change**
(it's internal orchestration). Flagging so nothing in the TUI is built assuming the contract
state machine.
